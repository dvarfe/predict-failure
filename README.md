# Predict-Failure: система предиктивного обслуживания оборудования

**Predict-Failure** — прототип платформы для мониторинга аппаратных компонентов и предсказания отказов с помощью методов анализа выживаемости.


**Краткий обзор**
- **Что делает проект**: собирает телеметрию (CPU, GPU, диски, батареи, события), хранит данные, обучает модели и выполняет прогнозы. Также предоставляет веб-интерфейс для визуализации и управления.
- **Кому это полезно**: инженерам по надежности, админам инфраструктуры, исследователям в области предиктивного обслуживания.

## Быстрый старт

**1. Клонирование репозитория**
```bash
git clone https://github.com/dvarfe/predict-failure
cd predict-failure
```

**2. Установка зависимостей**
```bash
pip install -r requirements.txt
```

**3. Настройка конфигурации**

Отредактируйте файл `storage/configs/config.json` и укажите устройства для мониторинга:

```json
{
    "system": "Linux",
    "enabled_collectors": [
        "cpu",
        "gpu", 
        "drive",
        "battery"
    ],
    "collectors": {
        "cpu": {
            "selected_objects": []  // пустой список = все CPU
        },
        "gpu": {
            "selected_objects": [
                "NVIDIA GeForce GTX 1650: 0",  // укажите ваши GPU
                "Intel GPU 0x3e9b: 0"
            ]
        },
        "drive": {
            "selected_objects": []  // пустой список = все диски
        },
        "battery": {
            "selected_objects": [
                "system_battery"  // укажите батареи для мониторинга
            ]
        }
    }
}
```

**4. Запуск системы**
```bash
# Запуск основного приложения с веб-интерфейсом
python run.py
```

После запуска веб-интерфейс будет доступен по адресу `http://localhost:11111`

**Основные возможности (функционал)**
- **Сбор данных**: набор коллекторов в `collectors/` собирает метрики с различных компонентов и сохраняет их в `storage/data/`.
- **Хранение данных**: сырые CSV и предобработанные датасеты хранятся в `storage/data/`; конфигурация — в `storage/configs/`.
- **Пайплайн подготовки данных**: в `modules/` и `modules/base/` содержатся базовые классы и провайдеры данных для приведения сырых логов к формату, пригодному для обучения.
- **Хранение моделей**: `model_storage/` реализует интерфейс сохранения/загрузки ML-артефактов.
- **Инференс / Прогнозирование**: в `modules/` и `core/` находятся компоненты для применения моделей к новым данным и получения прогнозов.
- **Веб-интерфейс и визуализация**: `templates/`, `static/` и `visualization/plots.py` реализуют UI и визуальные представления прогнозов и метрик.

**Структура проекта**

Проект имеет модульную архитектуру, основанную на абстрактных базовых классах. Основные компоненты:

- **`modules/base/`** — содержит абстрактные базовые классы для всех основных компонентов системы:
  - `collector_base.py` — базовый класс для сборщиков данных
  - `data_provider.py` — абстрактный класс для провайдеров данных
  - `model_base.py` — базовый класс для ML-моделей
  - `model_registry_base.py` — базовый класс для реестра моделей
  - `model_storage_base.py` — абстрактный класс для хранения моделей
  - `scheduler_base.py` — базовый класс для планировщиков задач
  - `feature_metadata.py` — работа с метаданными признаков

- **Реализации компонентов:**
  - `modules/collectors/` — конкретные реализации коллекторов (CPU, GPU, батареи, диски, события)
  - `modules/models/` — реализации ML-моделей (Cox, деревья, нейросети)
  - `modules/providers/` — провайдеры данных для загрузки и обработки
  - `modules/model_storage/` — системы хранения моделей
  - `modules/registry/` — реестр доступных моделей
  - `modules/schedulers/` — планировщики для выполнения задач

**Как добавить свою реализацию**

Для расширения функционала создайте новый класс, наследующийся от соответствующего базового класса из `modules/base/`. Например:

```python
from modules.base.collector_base import CollectorBase

class MyCustomCollector(CollectorBase):
    def collect(self):
        # Ваша логика сбора данных
        pass
```

**Конфигурация и настройки**

Выбор конкретных реализаций компонентов осуществляется через файл конфигурации `storage/configs/config.json`. В нем указываются:
- Типы используемых коллекторов
- Параметры моделей
- Настройки планировщиков
- Пути к данным и другие параметры системы

Дополнительные параметры логирования и пути можно менять в `core/config.py`.
